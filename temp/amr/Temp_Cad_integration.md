CAD 통합이 끝났습니다. **CAD 로봇도 로봇 1대를 추가할 때 늘어나는 CPU는 기존 모드와 같은 +9.6 %p이고, 50% 기준이면 4대까지입니다.** 다만 로봇끼리 가까워졌을 때 3분 넘게 서로 막혀 서는 일이 두 번 있었고, 원인은 아직 모릅니다. 사용자용 요약은 `isaac_fleet_ws/docs/CAD_SUMMARY.md`에 있습니다. 모드별 실행 명령, 검증 수치, 확인하지 않은 것도 거기 정리돼 있습니다.

**CPU 측정** (CAD 기본 모드 = PhysX 라이다 + scan A + AMCL, 대수별 15분, SCALING.md와 같은 방법)

| 대수 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- |
| 호스트 CPU (1분 평균) | 15.7 % | 24.4 % | 35.5 % | **45.3 %** | 55.2 % |
| 실시간 비율(RTF) | 1.0 | 1.0 | 1.0 | 1.0 | 0.994 |

- **로봇 1대 추가당 증가분:** Isaac 컨테이너 기준 +9.64 %p로, 기존 모드의 9.58과 같습니다. 호스트 기준 기울기는 9.99로 조금 크게 나왔습니다. 측정하는 동안 컨테이너 밖 배경 사용량이 서서히 올라서 섞인 값이라, 1대당 비용은 컨테이너 기준으로 보시면 됩니다.
- **고정비는 기존 모드보다 약 0.7 %p 낮습니다.** CAD 로봇은 함대 모드에서 외형 렌더링(visual)을 끄기 때문에 Isaac 프로세스가 가볍습니다. ROS 스택 비용은 기존과 같습니다.
- **손계산 식:** 호스트 CPU ≈ B + 3.4 + 9.6·N (기존 모드는 B + 4.4 + 9.6·N). B는 컨테이너 밖 배경 사용량으로, 이번 측정에서 약 2.8%였습니다.
- **대수:** 50%면 4대, 55%면 5대가 경계(실측 55.2%), 60%면 5대입니다.

**검증 결과**
- **라이다가 다른 로봇을 실제 CAD 외형대로 봅니다.**
  - 상대 로봇이 서 있는 구간에서, 기록된 스캔과 CAD 메쉬로 계산한 거리의 차이는 중앙값 0 mm, 95% 이내 0.2 mm 이하입니다.
  - 리뷰에서 레이캐스트를 따로 다시 계산해도 같은 결과가 나왔습니다.
  - CAD 형상은 바꾸지 않았습니다.
- **기존 gz-URDF 모드는 그대로입니다.** 같은 설정으로 다시 돌린 결과가 이전 판과 일치했습니다. 1대 판이 19.9%로 이전 16.1%보다 높게 나온 것은 그 시간에 데스크톱을 쓰고 있어서였습니다.
- **cartographer:** 위치 오차는 중앙값 1.5~2.2 cm, 95% 이내 4.3 cm입니다. CPU는 AMCL보다 로봇당 약 +1 %p 더 씁니다.
- **RTX 라이다 + scan B:** 1대에서는 실시간으로 돌지만, 2대에서는 RTF가 0.90으로 떨어지고 GPU 사용률이 80%입니다. 정밀 확인용으로 1대에서만 쓰시는 걸 권합니다.
- **기존 하네스 쪽:** 정리 단계에서 실행 기록(RUN_INFO)에 코드 버전 해시(md5)를 남기고, 모르는 인자나 오타가 들어오면 경고를 찍게 했습니다. 고친 뒤 기존 모드 1대 판으로 동작이 같은 것을 확인했습니다.
- **SIM_SAFETY_PLC 동작이 바뀌었습니다.** 이제 `stub`과 `emu` 외의 값은 실행을 멈춥니다. 예전에는 다른 값도 조용히 `stub`으로 돌았으니, 다른 값을 넘기는 스크립트가 있다면 그 판은 이제 시작되지 않습니다.

**확인이 필요한 것**
- **로봇끼리 가까이서 서로 막히는 일이 두 번 있었고, 원인은 모릅니다.** 2대 판에서 약 190초(2회 중 1회), 5대 판에서 약 218초 동안 막혔습니다. 하네스 감시 도구는 둘 다 잼으로 잡지 못했습니다. CAD 외형이 원인인지도 아직 알 수 없습니다.
- **cartographer 모드에서만 모퉁이 경고가 반복됩니다.** 레인 모퉁이에서 정적 장애물 충돌 판정 뒤 '조기 재개' 경고가 되풀이됩니다. 기존 로봇에서도 나오는 현상이라 CAD 로봇 탓은 아닙니다.
- **아직 시험하지 않은 것**
  - 안전 PLC의 보호 필드 정지와 STO: 판 중에 한 번도 걸리지 않았습니다.
  - 3대 이상 cartographer, RTX, scan B 조합
  - CAD 모드 40분 이상 롱런

지금 실행 중인 프로세스는 없고 netns도 정리돼 있습니다. 읽기 전용 폴더도 건드리지 않았습니다. claude_sim을 포함한 v2_ws에서 바뀐 것은 허락하신 amr-gz-sim-example 수정뿐입니다. 4개 관점의 리뷰 원문은 `isaac_fleet_ws/results/review/` 아래에 있습니다.
